# Sprint M2 — Movement and camera

Source: plan.md §6, §7.4, §9 (M2), §10 (M2 prompt); GDD §0, §1, §2; tiled-conventions.md (map size).
**Done when:** movement feels responsive and the camera never shows space outside the map.
No followers, enemies or combat in this milestone.

Done-when items used below:
- **D1** `typecheck`, `lint`, `test`, `build` all pass; movement math is in `src/core` with unit tests.
- **D2** Movement is responsive: velocity = input × `squad.moveSpeed` with no acceleration; diagonals
  are normalised (same speed as cardinals); the leader can't leave the world bounds.
- **D3** The camera follows smoothly with a deadzone, frame-rate independent, and never shows space
  outside the map: checked at all 4 map corners and at 3 viewport sizes.
- **D4** `GameInput` matches plan §6, and `KeyboardMouseInput` maps every action in the §6 table
  (including unused ones). `consume()` is edge-triggered, `aimWorld` is in world coordinates, and all
  listeners are removed on scene SHUTDOWN.
- **D5** Debug overlay toggles with `?debug` or backtick.

## Contract changes (producer, after human approval)

### `src/core/types.ts` — add
```ts
/** Axis-aligned rectangle in world pixels (world bounds, camera bounds, deadzones). */
export interface Rect {
  readonly x: number;
  readonly y: number;
  readonly width: number;
  readonly height: number;
}

/** Squad movement tuning (GDD §1, Q9: one squad speed). */
export interface MovementTuning {
  readonly squadMoveSpeed: number;      // px/s
  readonly wizardBodyRadiusPx: number;  // keeps the body inside world bounds
}

/** Camera follow tuning. */
export interface CameraTuning {
  readonly deadzoneWidthPx: number;
  readonly deadzoneHeightPx: number;
  readonly followHalfLifeMs: number;    // time to close half the gap; frame-rate independent
}
```
`succession.cameraEaseMs` (GDD §2) joins `CameraTuning` in M3, when succession exists.

### `src/game/events.ts` — deferred to M3
No M2 system emits anything another system listens to: input → leader → camera is one direct
chain the scene sets up. The first real event is `squad:leader-changed` (M3), and the bus gets
created then. (Creating an empty event map now would be contract churn with nothing to check.)

## Creative-director playtest (2026-10-15)
Feedback: movement feels OK. The wizard is cut off up to its feet at the top edge, which is too much.
The camera should pan further ahead when moving. The crosshair isn't visible at all.

Decisions (CD-approved):
- **Look-ahead:** `CameraTuning` gains `lookAheadPx` and `lookAheadHalfLifeMs` (contract change,
  approved). Starting values are 64 px and 250 ms. The camera aims at the leader plus the smoothed move
  direction × lookAheadPx. The deadzone applies to that point.
- **Top edge:** the leader can't walk closer to a map edge than its visible sprite. Top inset = the
  sprite extent above the feet (46 px); sides and bottom stay at the body radius. M7's blocker
  perimeter makes this redundant on real maps.
