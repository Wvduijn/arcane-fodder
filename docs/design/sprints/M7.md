## Architecture (short plan, CLAUDE.md "present a plan before any architectural change")

- **New core folder `src/core/world/`**: `collisionGrid.ts` (solid tiles from the `blockers` layer,
  plus dynamic solids for kegs; circle-vs-tile push-out with sliding; segment cast for projectiles and
  line of sight; nearest free tile) and `flowField.ts` (Q2: BFS distance field on the tile grid toward
  the wizards, 8-way without corner cutting, rebuilt on a fixed interval; enemies sample it when the
  straight line to their target is blocked). Pure, typed-array based, tested.
- **Collision is applied in core steps, not Phaser physics.** Squad step: the leader slides along
  blockers; followers keep the breadcrumb rule (GDD §1: the trail is walkable) and are pushed out of
  solids. Enemy step: walk (flow field when blocked) → separate → yield → push out of solids → clamp.
  Projectiles (autos, arrows, Fireball) end on the first solid tile along their frame segment.
  Phaser stays a renderer, as since M2.
- **New core folder `src/core/mission/`**: `mapData.ts` (Tiled JSON `unknown` → typed `MissionMap` +
  all `tiled-conventions.md` §6 validation rules; game-dev's loader only reads the JSON and calls it),
  `objectives.ts` (progress by `TargetId`), `portal.ts` (sealed → opening → open → extracted; trigger
  check; extraction split), `surge.ts` (schedule from surge-spawn objects, delayMs, 160 px skip with
  share shift, alive cap), `mission.ts` (phases intro → playing → ended, paused-aware timer, kills,
  defeat rule, `MissionResult` builder, best time).
- **Huts in core `src/core/structures/hut.ts`**: spawner state machine (inactive → active →
  tell → spawn, max alive, door fallback via `nearestFreeTile`, destroyed). A hut is a `CombatWorld`
  unit (team `enemy`, HP 300, takes Burning) flagged as a structure: its death emits **`hut:destroyed`,
  never `unit:died`**, so kills (+4 meter each, results count) stay enemy units only.
- **Systems (game):** `TilemapLoader` (Boot loads the JSON, placeholder tileset textures are made at
  boot), `CollisionSystem`/`NavigationSystem` wrapping the core grid and flow field, `SpawnerSystem`
  (huts, enemy-spawn groups, triggers, archer posts), `MissionSystem` (objectives, timer, end
  conditions, results), `PortalSystem` (runes, opening, surge, ring, extraction), `ResultsScene`.
  Frame order gains: input → **mission (phase, triggers)** → squad → enemies → **spawner** →
  targeting → Convergence → Volunteer! → spells → kegs → combat → statuses → **portal (extraction
  check after deaths)** → HUD → views → camera → debug.
- **MissionScene runs a `MissionDef`.** Roster, name seed and positions come from mission data and
  the map; the dev arena constants stay only as test fixtures (Q5).
- **Hat Hill:** combat deaths are appended when they happen (like volunteers since M6), left-behind
  wizards at extraction. So an abandoned run still remembers its dead and nothing is written twice.

## Contracts (producer applies after CD approval, Q8)

### src/core/types.ts
```ts
export type MissionId = 'dev-arena' | 'm01-goblin-woods';   // dev-arena kept (CD 2026-10-21)
export type StructureId = 'powder-keg' | 'goblin-hut';
/** What a destroy objective counts (plan §4.4). MVP: huts only. */
export type TargetId = 'goblin-hut';
export type MissionOutcome = 'victory' | 'defeat';
/** 'always': ignores aggroRadiusPx and converges from spawn (GDD §13, ADR 0007). */
export type WaveAggro = 'radius' | 'always';

/** Goblin Hut (GDD §12). Tiled `goblin-hut` properties may override the spawn fields per hut. */
export interface HutDef {
  readonly id: 'goblin-hut';
  readonly target: TargetId;
  readonly maxHp: number;
  readonly footprintPx: number;
  readonly bodyRadiusPx: number;
  readonly activateRadiusPx: number;
  readonly firstSpawnDelayMs: number;
  readonly spawnIntervalMs: number;
  readonly maxAlive: number;
  readonly spawnTellMs: number;
  readonly spawnEnemy: EnemyId;
}

/** Portal and surge tuning (GDD §13). Per-mission numbers live in MissionDef. */
export interface PortalTuning {
  readonly openingMs: number;          // 1500
  readonly triggerRadiusPx: number;    // 24
  readonly introPanMs: number;         // 3000, skippable
}
export interface SurgeTuning {
  readonly minSpawnDistancePx: number; // 160
  readonly maxAlive: number;           // 12 (GDD power curve: peak on screen ≤ 12)
}

export interface DestroyObjectiveDef {
  readonly kind: 'destroy';
  readonly target: TargetId;
  readonly count: number;
}
export type ObjectiveDef = DestroyObjectiveDef;

export interface FinalSurgeDef {
  /** Every `surge-spawn` whose `wave` equals this id. */
  readonly waveId: string;
  readonly spawnPoints: 'all-remaining';
  readonly aggro: WaveAggro;
}
export interface PortalExtractionDef {
  readonly kind: 'portal';
  /** Name of the `portal` map object. */
  readonly spawnId: string;
  readonly radiusPx: number;
  readonly finalSurge: FinalSurgeDef;
}

/** One mission (plan §4.4): what it is. The map holds where. */
export interface MissionDef {
  readonly id: MissionId;
  readonly name: string;
  /** Relative to public/assets/. */
  readonly map: string;
  /** Leader first (GDD Q18). */
  readonly squad: readonly MageClassId[];
  /** Restart n uses nameSeed + n (GDD Q17). */
  readonly nameSeed: number;
  readonly start?: { readonly spawnId: string };
  readonly objectives: readonly ObjectiveDef[];
  readonly extraction: PortalExtractionDef;
}

/** Results screen input (GDD §14), built by core at mission end. */
export interface WizardRecord {
  readonly name: string;
  readonly classId: MageClassId;
}
export interface LostWizardRecord extends WizardRecord {
  readonly cause: DeathCause;
}
export interface MissionResult {
  readonly missionId: MissionId;
  readonly outcome: MissionOutcome;
  /** Pause excluded. */
  readonly timeMs: number;
  /** Enemy units only. */
  readonly kills: number;
  readonly targetsDestroyed: number;
  readonly targetsRequired: number;
  readonly saved: readonly WizardRecord[];
  /** In order of loss. */
  readonly lost: readonly LostWizardRecord[];
  readonly bestTimeMs: number | null;
  readonly newBest: boolean;
}
```
`DevEncounterSpawn`/`DevKegSpawn`/`DevSquadConfig` stay (test fixtures).

### src/game/events.ts (replaces the plan's "Planned (M7)" block)
```ts
/** A hut reached 0 HP: spawning stops, rubble stays. Never followed by `unit:died` (huts aren't kills). */
'hut:destroyed': { readonly id: EntityId; readonly target: TargetId; readonly at: Vec2 };
/** One objective target down; `progress` of `required`. The portal lights rune `progress − 1`. */
'mission:target-destroyed': {
  readonly target: TargetId; readonly progress: number; readonly required: number; readonly at: Vec2;
};
/** The opening starts: surge spawns, meter +chargeOnPortalOpen. Enterable after PORTAL.openingMs. */
'portal:opened': { readonly at: Vec2 };
/** The leader reached the portal. Left-behind wizards get no `unit:died` (they aren't killed). */
'portal:extracted': { readonly saved: readonly EntityId[]; readonly leftBehind: readonly EntityId[] };
/** Victory after extraction, defeat when the squad is gone and no volunteer runs (GDD §14). */
'mission:ended': { readonly result: MissionOutcome };
```
Rune order: GDD §13 "lights the next rune (left to right)" wins over Tiled `runeIndex`; the loader
still validates `runeIndex` (conventions rule 2), and rune slots are laid out by it.

## Design questions for the human
- **Q1, map authoring.** level-designer has no shell, and a 128×96 map with 4 layers is ~50k numbers
  of Tiled JSON. *Recommended:* level-designer writes a readable source: a 128×96 ASCII terrain grid
  (one char per tile) + an objects JSON in `assets-src/levels/m01-goblin-woods/` (new path, owner
  level-designer); game-dev writes `scripts/levels/build-tilemap.mjs` (owner game-dev) that emits a
  proper Tiled JSON to `public/assets/tilemaps/` (still openable in Tiled); `pnpm maps:build` is
  allowed in settings. Alternative: the CD draws the map in Tiled from the level doc.
- **Q2, enemy navigation.** Nothing pathfinds today; with tree walls, chasing goblins and the
  aggro-`always` surge get stuck behind trees. *Recommended:* a flow field toward the squad on the
  tile grid (core, rebuilt every 250 ms, used only when the straight line is blocked). Alternatives:
  wall-slide only (cheap, surge will pile up on walls), or no aggro-`always` (breaks GDD §13).
- **Q3, line of sight.** *Recommended:* blockers block **target selection** for wizard autos and
  archer draws (the level doc's ravine trunks "break line of sight"), aggro does not (goblins hear
  you). Without it, followers fire autos into trees all mission.
- **Q4, tuning data owner.** Hut/portal/surge numbers go in `src/data` (game-designer's), but
  game-designer isn't on the M7 team. *Recommended:* spawn game-designer for T1 only (30 min, every
  number already approved in GDD §12/§13, plus `introPanMs` 3000 and `maxAlive` 12 from the level
  doc), then shut it down. Alternative: the producer transcribes the values (breaks "designers own
  numbers").
- **Q5, dev arena.** *Recommended:* retire the dev arena at runtime (the map covers every fight;
  debug keys cover quick tests); `devArena.ts` stays as test fixtures, `'dev-arena'` stays in
  `MissionId`.
- **Q6, pause.** GDD §14 says time excludes pause and restart is also in the pause menu, but there's
  no pause yet (Esc/P is bound, does nothing). *Recommended:* minimal pause in M7: Esc/P freezes the
  mission scene, overlay with Resume / Restart. Alternative: defer to M9 (timer then never pauses).
- **Q7, Hat Hill timing.** *Recommended:* combat deaths are written when they happen (as volunteers
  are), left-behind at extraction, so a restarted run still keeps its dead and nothing is written twice.
  Alternative: write everything at mission end (GDD §14 wording; an abandoned run loses its dead).
- **Q8, contracts.** Approve the `types.ts` and `events.ts` changes above, and the plan.md §7.4 refresh.
