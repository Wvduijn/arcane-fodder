### Minor

**m1. favicon.ico 404 shows up as a console error on every load.** (owner: game-dev)
index.html has no icon link, so the browser requests `/favicon.ico` and logs
`Failed to load resource … 404`. It's harmless, but it will be noise in every console-error check
from here to M9 (the review gate counts console errors).
Fix: add `<link rel="icon" href="data:," />` to index.html `<head>` now. Replace it with a real
icon in M8.

### Nits

- **config.ts:18-19 `roundPixels: true` is redundant.** `pixelArt: true` already sets it
  (node_modules/phaser/src/core/Config.js:395-403: "When enabled, this also sets `antialias` and
  `antialiasGL` to `false` and `roundPixels` to `true`"). It's harmless and explicit, but the
  comment suggests it is needed. Either drop it or reword the comment to "explicit, though implied
  by pixelArt".
- **placeholders.ts:32 eye colour `#1b1f2a` equals `BACKGROUND_COLOR` (config.ts:8).** The eyes
  render as holes through the face. That's fine for a placeholder; mentioned only so nobody reads
  it as a rendering bug.
- **main.ts:2 uses a relative `./app/config`, while registry.ts uses the `@game/…` alias.** No
  `@app` alias exists, so relative is correct. Mentioned only for consistency if an `@app` alias is
  ever added (that would be a contract change through the producer).

### Observations for the human (no action required in M1)

**O1. Texels are crisp but not uniform at non-integer FIT scales.** At 1280×720 and 2560×1440
the display scale is a whole number (2×, 4×) and every texel is the same size. On a phone (390×844
portrait gives 0.61×; 844×390 landscape gives 1.08×) FIT scales by a fraction. Nearest-neighbour
sampling keeps the colours pure (no blur, verified above), but some texel columns come out 1 device
pixel wider than others (7 vs 8 px, 12 vs 13 px). That's what you'd expect from `Scale.FIT` and
it is within D2. If the human wants uniform pixels on mobile, the M8/M9 options are an integer
zoom with letterboxing (`Scale.NONE` plus a manual integer zoom), or `Scale.FIT` with a camera
zoom snapped to a whole number. That is a design question, not a defect.

**O2. Portrait is very small.** In 390×844 portrait the playfield is 390×219 CSS px, about a
quarter of the screen. That's correct for a landscape game, but it suggests an orientation lock
or a "rotate your device" prompt in M8/M9.
