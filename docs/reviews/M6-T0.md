## Findings

### Blocker
None.

### Major

**M1. `convergence:impact` cannot tell a Firestorm meteorlet from a Firestorm bolt.** (owner:
producer, contract change → CD approval; affects game-dev T11)
T11 needs different FX for meteorlets (fire, falling rock) and bolts (storm, reuse the M5 Lightning
bolt). Both arrive as `{ combo: 'firestorm', at, radiusPx }`. The only way for the view to tell them
apart is to compare `radiusPx` against `CONVERGENCES` data (40 vs 20), which breaks as soon as the
designer tunes a radius to match, and puts a data-matching rule in the view. Fix: add
`readonly element: DamageElement` (the blast's element) to `convergence:impact`. It is enough for
all three combos (Meteor impact fire, Thunderstorm storm, Firestorm both) and the M5 bolt FX
already keys on storm. Needs the CD's OK since the event shapes were approved as written; it only
has to land before T11.

### Minor

**m1. plan.md §7.2 `CONVERGENCES` example is now stale.** (owner: producer, plan edit → CD approval)
plan.md:385-392 still shows `{ baseDamage, radius }` entries and a separate `CONVERGENCE_SCALING`
constant, while the contract now has `radiusPx` + `pattern` and `ConvergenceTuning.scaling`. A
reader following plan.md (the source of truth) would build the old shape. Fix: replace the example
with one entry in the new shape and point `CONVERGENCE_SCALING` at `CONVERGENCE.scaling`, or add a
line "shape superseded by ConvergenceDef in src/core/types.ts (M6)".

**m2. plan.md §7.4 save comment says `'volunteered'`.** (owner: producer)
plan.md:445 lists `cause: 'combat' | 'volunteered' | 'left-behind'`; `DeathCause` is `'volunteer'`.
Harmless today (core-dev types the save from `DeathCause`), but it is the one place a string
literal could drift into the save format. Fix with m1's edit.

**m3. GDD §11 names `volunteer.damage`, `volunteer.radiusPx`, `volunteer.knockbackPx`.** (owner:
game-designer, T1)
The contract nests them as `VOLUNTEER.blast.damage / .radiusPx / .knockbackPx` (plus
`blast.element: 'arcane'`, `blast.canGib`). M6.md T1 says the GDD tables name the data keys, so the
§11 table should be updated in T1. Same for GDD §10 if it is meant to name `pattern.*` keys.

### Nit

**n1. `bestTimes: Record<MissionId, number>` in plan §7.4.** (owner: core-dev, T7)
With `MissionId` a closed union, a full `Record` forces a time for every mission, including ones
not yet played, and `dev-arena` will linger in saves once M7 widens the union. Suggest
`Partial<Record<MissionId, number>>` in `SaveDataV1`, and `migrate` dropping unknown mission ids in
both `bestTimes` and `hatHill` rather than failing.
