### Minor

**m1. A unit killed earlier in the frame still absorbs later projectiles that frame.** (owner: game-dev; D4)
`stepProjectiles` builds `bodies()` once per frame with `alive: true` (CombatSystem.ts:231, :284). If
projectile A kills goblin G, `CombatWorld` marks G dead, but projectile B, stepped later in the same
loop, still sees G as a live body. It "hits" it, `applyHit` refuses (counted in `refusedHits`), and B is
released instead of flying on to the next goblin. D4 says a dead unit is never *hit*, and the
headless sim does this correctly: it re-reads `world.isAlive` for every projectile
(tests/core/combat/encounterSim.ts:265). So game and sim diverge here. It didn't occur in my 3 runs
(`refusedHits` 0), but four wizards focusing one goblin make it a matter of time.
Fix: pass `alive: this.world.isAlive(body.id)` per projectile step (as the sim does), or drop the body
from the list when a hit kills it. One line; a `refusedHits === 0` assertion in the gate then becomes
meaningful.

### Nit

**n1. Burning's first tick is one frame early in game.** Inherited from M4-T4 m1 (core-dev, open):
`applyStatus` here (:261) is followed by `StatusSystem`'s `stepStatuses` in the same frame. No game
change is needed once the core fix lands.

**n2. The `unit:damaged` team fallback `'neutral'`** (:156) can't happen for a landed hit (the unit
exists). Harmless; a non-null assertion or an early return would say so.
