## Verdict: PASS WITH NOTES

The parser takes `unknown` and never trusts it. Every problem is collected, not just the first,
with its rule number and object name. `map` is null on any error. Format checks cover:
orientation, finite size, square tiles, required layers and their kinds, plain or uncompressed
base64 data (compressed data is refused with a clear message), objects on the wrong layer, wrong
geometry, tile objects, the Tiled `class` fallback, and both property shapes.

All seven contract rules are implemented as conventions §6 states them:
- Rule 1 uses the mission's spawn ids.
- Rule 2 checks the count, unique and complete `runeIndex` values, and the portal's `runeCount`;
  a radius mismatch is a warning.
- Rules 3, 4 and 5 are as written.
- Rule 6 warns and exempts huts.
- Rule 7 covers kegs in `safe-start` and within 192 px of the start.

The "96 px from the route centreline" part of rule 7 is explicitly not machine-checked, which the
producer accepted in the follow-ups. Exhaustive `Record<EnemyId|TargetId, true>` tables make a
new id fail to compile until it is listed, the same pattern as save.ts.

My T3 m3 request is in: the real-map test asserts `squad-start`, `portal` and `surge-01` resolve
(`mapData.test.ts:663-667`). A second test checks that every spawn reaches the portal on the
flow field.

## Findings

### Major

**M1. The real-map tests are `it.skipIf(!m01Exists)`** — `tests/core/mission/mapData.test.ts:655`
and `:675`. D1 requires "the real m01 JSON passes". With `skipIf`, a missing, renamed or
uncommitted map turns both tests into a silent skip and the suite stays green. `public/` is
untracked in git right now (`?? public/`), so a fresh checkout of the commit as it stands would
skip them. CLAUDE.md: never skip tests to make the build pass.
Fix: now that T5 has landed, drop the `skipIf` so a missing file fails loudly (`readFileSync`
throws). The producer should make sure `public/assets/tilemaps/m01-goblin-woods.json` is part of
the M7 commit. Owner: **core-dev** (test), **main** (commit).

### Minor

**m1. Enemy spawns inside `safe-start` aren't checked** — conventions §4.3: "`safe-start`: No
enemy may spawn or path-aim inside". `checkKegs` (`mapData.ts:910-933`) only checks kegs. m01 is
fine (`grunts-stray-01` at (460,1320) lies outside (112..272, 1264..1424)), but nothing guards
the next map.
Fix: add a rule-7 error (or a warning, the producer's call) for any `enemy-spawn`, `archer-post`
or `surge-spawn` point inside a `safe-start` rect. Owner: **core-dev**.

**m2. No 1-tile gap warning** (see M7-T7 m2). It is optional, and would fit next to rule 6 here.
Owner: **core-dev**.
