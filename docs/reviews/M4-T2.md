### Nit

**n1. Leftover frame time is dropped on a transition.** (owner: core-dev, for T7; D5)
stateMachine.ts:66-67: after a transition the new state's `update` runs with `dt 0` and
`timeInStateMs 0`, so the part of the frame after the switch is never credited to the new state.
A 150 ms wind-up therefore lasts 150 ms plus up to one frame (≤ 33 ms at 30 fps, ≤ 100 ms at the
clamp). That's deterministic and fine for a tell (readability wants ≥ 100 ms, not exactly 150), but
T7 tests that assert "release at exactly windupMs" must allow one frame of slack at 30 fps, and the
draw-aim lock time is at frame granularity. No code change needed; mention it in T7's doc comment.

**n2. `NaN` dt is not guarded.** (owner: core-dev)
stateMachine.ts:56-57: `Math.max(0, NaN)` is `NaN`, which would make `timeInStateMs` NaN forever
and freeze every timed state. The scene clamp (`COMBAT.maxFrameDtMs`, T9) should make it
impossible, so this is only defensive. Optional: `Number.isFinite(dtMs) ? Math.max(0, dtMs) : 0`.

**n3. One `Set` allocated per step per unit.** (owner: core-dev)
stateMachine.ts:54. At 8–20 goblins it's negligible. If profiling ever shows GC churn in M7's
waves, a chain is at most `|states|` long and a small array or bitmask would do. No action now.
