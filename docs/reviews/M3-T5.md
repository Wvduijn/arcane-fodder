## Verdict: PASS

The roster is an immutable `readonly EntityId[]` with pure functions. Same-frame multi-deaths promote
the lowest surviving index, killing the last member leaves a cleanly empty roster, and unknown, dead
or repeated ids are no-ops that return the same roster reference. The result type is a discriminated
union, so `leaderChanged: true` guarantees a non-null `newLeader` at compile time. The added `killed`
list, in ascending id order, gives game-dev a deterministic order for emitting `unit:died` (GDD §0).

### Nit

**n1. Name differs from the sprint text.** The sprint says `kill(ids[])`, and the code says
`killMembers`. That's clearer, and the module's API doc lists it. No change needed. I'm noting it so
T8 isn't hunting for `kill` in core. (`SquadSystem.kill(ids)` in game is a separate method and keeps
the sprint's name.)

## Notes for T8/T9 (game-dev)
- On a wipe, `leaderChanged` is `false` and `newLeader` is `null`, but `killed` contains the old
  leader. The camera hold and the marker hide (T9) must therefore key off `newLeader === null` or an
  empty roster, not off `leaderChanged`. Don't emit `squad:leader-changed` on a wipe: its payload id
  isn't nullable.
- Emit `unit:died` in `killed` order, so same-frame deaths resolve in ascending EntityId order (GDD §0).
- Use one `createIdAllocator()` per scene run, created in `create()`, so a restart starts over from 1.
  I'll look for that in the restart check.
