## Verdict: PASS WITH NOTES

The core is clean and pure (no Phaser/DOM). It's dt-independent by construction:
- Travel is capped by the remaining fuse, so the four detonation triggers are ordered in time,
  not by check order.
- Contact is a swept circle test, so a 500 ms frame can't tunnel through an enemy.
- Fuse and arrival land on exact points at 30/60/144 fps.

`pickVolunteer` never returns the leader (sizes 0–4 plus a 200-roster fuzz). Spell loss on
activation falls out of `spellSlots` with no stored flag (P,S,P,S keeps both; P,P,S,S loses
Lightning on the 2nd; P,S loses it at once). The hold freezes the leader and followers to zero
velocity, still plays knockback out in full and resumes follow cleanly. Denials come in the
documented order and change nothing.

No blockers. One **major**: a volunteer killed by enemies mid-sprint gets `unit:died` with cause
`combat`, not `volunteer`. The design (GDD §11, events.ts) needs `volunteer`, and nothing in the
core API provides it. It needs a decision before T12.

## Findings

### Blocker
None.

### Major

**M1. Enemy-killed volunteers die with cause `combat`, not `volunteer`.** (owner: core-dev,
with game-dev for T12; producer if the event doc changes)
A runner stays a live squad-team unit in the CombatWorld (by design, "my calls"). When a goblin's
hit brings it to 0 HP, CombatSystem's flush builds the `DeathRecord` from the hit, with cause
`'combat'` (death.ts: only `killUnit` takes a cause), and emits `unit:died` at once. On the next
frame `stepVolunteers` sees `isAlive === false` and returns a `death` detonation. But the
module's own contract (volunteer.ts:4-5: "then kills the volunteer with cause `volunteer`
(`killUnit`)") can't apply: `killUnit` returns null for a dead unit. Results:
- `unit:died.cause` is `combat` for a wizard who volunteered. GDD §11 says "they still count as
  volunteered", and Hat Hill and results share one cause list (GDD §15). D4 needs cause `volunteer`.
- Event order is reversed from events.ts ("`volunteer:detonated` … `unit:died` with cause
  `volunteer` follows in the same flush"): here `unit:died` comes first, one frame earlier.
- The blast goes off one frame after the corpse appears (cosmetic, but visible at 30 fps).

Suggested fix (core): let the death path know about runners. For example, an optional
`causeOverride: (id) => DeathCause | undefined` on the area/hit resolution (or a `runners` set on
CombatWorld) makes a runner's lethal hit resolve as cause `volunteer`, with its record held for the
volunteer system. Then `stepVolunteers` (or the same flush) detonates at that position in the same
frame and emits `volunteer:detonated` before `unit:died`. Add a test: runner at 1 HP takes a goblin
hit, and the outcome is exactly one death record, cause `volunteer`, plus a detonation at the hit
position the same frame. If the producer would rather accept cause `combat` in `unit:died` and
record the Hat Hill entry as `volunteer` from `volunteer:detonated`, the events.ts doc and GDD §15
"one cause list" need to change (CD).

### Minor

**m1. The runner ignores the walkable bounds.** (owner: core-dev)
`stepSquad` clamps to `input.walkable`, but `stepVolunteers` has no bounds, and the aim is only
clamped to 280 px from the leader. In the dev arena, aiming past the edge sends the rookie off the
playable rect until the fuse runs out. Fix: clamp the target (or the step) to the same `walkable`
rect, with one test. M7's collision layer will supersede this, so a doc line plus clamp is enough.

**m2. Volunteer contact uses the caller's body list, with nothing enforcing "enemy only".**
(owner: core-dev, for game-dev T12)
`VolunteerStepInput.contacts` is documented as "living enemy units and huts", but a caller passing
`combatWorld` bodies unfiltered would make the runner detonate on its own squad or a keg. Fix:
either take `AreaBody & { team }` and filter `team === 'enemy'` inside, or keep it and I'll check
the T12 call site. A test with a squad body on the path would pin it.

### Nit

**n1. The bark data test is still open** (M6-T1-T2 m2). `pickBark` is tested with counts, not
against `VOLUNTEER_BARKS`. I'll check it in T12 if it's not added before.
