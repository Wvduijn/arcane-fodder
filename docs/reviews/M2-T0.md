### Minor

**m1. `Rect` does not say which point `x`, `y` is.** (owner: producer, contract)
src/core/types.ts:12. Phaser's `Rectangle` and `camera.setBounds` use the top-left corner, but a
deadzone is naturally described around a centre, and the sprint says `Rect` is used for
deadzones too. If T2's `clampToRect` and T5's deadzone code pick different conventions, nothing
in the type system will catch it.
Fix: extend the doc comment to "`x`, `y` is the top-left corner; `width`, `height` are ≥ 0."
This only changes a comment, so it shouldn't need a new human approval round. Your call.

**m2. Naming drift between the GDD and the contract.** (owner: producer, to route to game-designer if wanted)
GDD mvp.md:74 says "the leader moves at `squad.moveSpeed`", and §0 calls the radius
`bodyRadiusPx` per unit. The approved contract uses `MovementTuning.squadMoveSpeed` and
`wizardBodyRadiusPx`. That's fine for M2. The risk is M4: when unit definitions get a
`bodyRadiusPx` (GDD §0 table, wizard = 10), the wizard radius will exist in two places.
Fix: when the M4 unit/class contract lands, make `wizardBodyRadiusPx` come from that one source
(or delete it from `MovementTuning`) rather than keeping two 10s in sync. Add a line to the GDD
now pointing `squad.moveSpeed` at `MOVEMENT.squadMoveSpeed`.
