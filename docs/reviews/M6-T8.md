## Design findings (already sent to main and game-designer by core-dev; noted here)

- **Firestorm never shows Combust on MVP goblins.** A meteorlet at ×1.5 or more (53+) one-shots
  grunts and archers before a bolt can pop them. The showcase of GDD §10 ("meteorlets burn, bolts
  pop them") only appears on huts in M7. It's the designer's and CD's call whether that's fine.
- **The dev fight leaves the meter at 78/100.** "Starting at 40 means the first fight fills it"
  (GDD §9) doesn't hold for DEV_ENCOUNTER: 6 grunts give 38.4. The archers are untouched in the
  no-input fight, which accounts for part of the gap. Tuning call for game-designer (or accept,
  since M7's Goblin Woods sections are bigger).

## Findings

### Blocker

### Major

**M1 (carried from M6-T6 M1). The "killed mid-sprint" sim still gives cause `combat`.**
(owner: core-dev)
convergenceSim.test.ts:282 kills the runner with `killWizards` (spellSim.ts:329,
`killUnit(…, 'combat')`). It then asserts only the detonation, not the death record. The sim's own
`volunteerStep` then calls `killUnit(d.id, 'volunteer')`, which returns null for the dead unit. So
the runner's only `unit:died` is cause `combat`, before the detonation. This is the M6-T6 M1
path, and this test is where it should be pinned. Fix: once the core fix lands (or the producer
decides), extend :282 to assert that `sim.deaths` has exactly one squad record for the runner,
with cause `volunteer`, in the same frame as the detonation. Better still, kill the runner with an
enemy-sourced hit, not a debug kill, since that's the in-game path.

### Minor

**m1. The sim doesn't tick statuses, so "the Burning they apply never charges" isn't exercised
end to end.** (owner: core-dev)
SpellSim (and so M6Sim) has no `stepStatuses`. Meteor's Burning, the burning ground and
Firestorm's meteorlet Burning never tick, so nothing checks that their tick damage arrives with
the Convergence id and is ignored by the meter, or that the Burning a Combust spreads (reaction id)
does charge. The unit tests cover each piece (meter.test.ts, area.test.ts, status source on
refresh). The join is what T10 will build, though. Fix: step statuses in M6Sim after the death
flush (as encounterSim.ts:440 does) and add one Meteor test: the meter stays at 0 through 4 s of
burning ground on 300 HP stand-ins, while `unit:damaged` from ticks is > 0.

### Nit

**n1. The per-composition test checks `dead.length > 0` only.** It's fine as a smoke check, and
:76 is stronger for ×2+. For ×1.0 (P, S) it could log the kill count so a tuning change that drops
Meteor ×1 kills to 0 is visible (and it would fail, which is correct).

**n2. `console.info` in a test.** It's intentional (the GDD §16 log) and it matches the M5 sims'
logs. No action.
