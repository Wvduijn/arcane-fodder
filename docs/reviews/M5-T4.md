## Verdict: PASS WITH NOTES

`resolveAreaEvent` is a single entry point built on one `applyEventHits` call, so every blast keeps
its per-event gib cap. It filters by team, applies a per-team damage multiplier, and puts status and
knockback on survivors only, in ascending id order. It excludes the Combust origin from the status
on request, and credits `sourceId` for both damage and status (the keg id for Kaboom, which makes
Burning-tick kills squad-side). `bodiesInRadius` is generic, so kegs use it too. The `damage.ts`
change keeps M4 behaviour: a plain `Hit` goes down the same path, and `gibsOnKill` receives the same
object. No existing caller or test changed (`git diff --stat -- tests/` is empty). Every M4 caller
(`CombatSystem.applyHit`, `StatusSystem`, the encounter sim) uses `applyHit`, whose code is
unchanged. One minor on integer HP, and some test-data nits.

## Findings

### Blocker

### Major

### Minor

**m1. A multiplied damage can make HP fractional.** (owner: core-dev; D5)
area.ts:131 computes `blast.damage * factor` without rounding, and the module comment relies on
"data keeps the products whole (60 × 0.5 = 30)". GDD §0 defines HP as an integer. If
game-designer retunes Kaboom to 55, a wizard would take 27.5, end on fractional HP, and the health
bar and `unit:damaged.amount` would carry non-integers. Nothing guards the assumption, and the
designer can't see it from data. Fix, either:
(a) round in core (`Math.round`, matching however M4 handles fractional damage, if it does), with a
test; or
(b) add a data test that `REACTIONS.kaboom.blast.damage × squadDamageMultiplier` is an integer, so a
retune fails loudly.
(a) is the safer of the two.

### Nit

**n1. The gib-cap-across-multipliers test doesn't exercise a multiplied gib check.** (owner: core-dev)
area.test.ts "the gib cap counts the whole event across damage multipliers" puts all 6 grunts at
×1, and the wizard can never gib anyway. So the new path, where `isGibKill` uses the *per-unit*
hit, isn't exercised: no test shows a multiplied hit dropping below the overkill ratio and not
gibbing. Suggest a case with `damageMultiplier: { enemy: 0.5 }` on Kaboom (30 < 1.5 × 24 = 36), so
grunts die without gibs.

**n2. The tests hard-code blasts and the keg radius that now live in data.** (owner: core-dev)
area.test.ts:23 (`KEG_R = 8`, "KEG data lands with M5 T1") and the `FIREBALL`/`LIGHTNING`/`KABOOM`
blasts (:26-48) were placeholders until T1. T1 has landed (M5-T1.md). Read `KEG.bodyRadiusPx`,
`SPELLS.*` and `REACTIONS.*.blast`, so the GDD reach checks follow the real data. If the intent is
to pin GDD numbers, keep the literal reach values (56, 18, 20, 82, 80) as the expectations and take
the radii from data. Then a retune that breaks a GDD reach claim fails the test.
