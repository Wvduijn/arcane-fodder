### Minor

**m1. Dynamic `import('phaser')` passes the core boundary.** (owner: game-dev)
eslint.config.js:52-75. `no-restricted-imports` does not inspect `ImportExpression`, so
`export const p = import('phaser');` in src/core lints clean.
Fix: in the src/core block, add
`'no-restricted-syntax': ['error', { selector: "ImportExpression[source.value=/^(phaser|@game|@platform|@data)(\\/|$)/]", message: '…§7.3' }]`.
Do the same for src/data, mirroring its allow-list.

**m2. src/core can use DOM globals and Node built-ins.** (owner: game-dev)
eslint.config.js:33-35 gives every `src/**/*.ts` `globals.browser`, and nothing restricts `node:*`
in core. `window.innerWidth`, `document.body`, `localStorage.getItem()` and `import 'node:fs'` all
lint clean in src/core. CLAUDE.md says "src/core is pure TypeScript: no Phaser, DOM or platform
imports". typescript-eslint turns off `no-undef`, so removing the globals is not enough.
Fix: in the src/core block, add `no-restricted-globals` for `window`, `document`, `navigator`,
`localStorage`, `sessionStorage`, `requestAnimationFrame`, `performance`, `process`, `Buffer`, and
add `group: ['node:*']` to its `no-restricted-imports` patterns.

**m3. Relative imports of `src/main.ts` (and `src/styles/`) are not covered.** (owner: game-dev)
eslint.config.js:9-10, 68, 93. `relativeInto` only lists directories, so `../main` from
src/core and `../main` / `../../main` from src/data are allowed. main.ts is the top of the
dependency graph.
Fix: append `'**/main'`, `'**/main.ts'` and `relativeInto(['styles'])` to the core and data
relative groups. Ask core-dev to add one case for this to tests/tooling/boundaries.test.ts.

**m4. `@types/node` is global to all of src.** (owner: game-dev)
tsconfig.json:6 `"types": ["vite/client", "node"]` applies to src/core and src/game too, so
`process.env`, `Buffer` etc. typecheck in runtime code that ships to the browser.
Fix (can wait until it bites): give tests/ and vite.config.ts their own tsconfig (e.g.
`tsconfig.node.json` with `types: ["node"]`) and keep only `vite/client` in the app tsconfig.
Lower priority if m2's lint guard on `process`/`Buffer` lands.

**m5. `passWithNoTests: true` can mask a broken test glob.** (owner: game-dev)
vite.config.ts:22. This made sense before any tests existed. Now there are 40 tests, so if the
`include` glob stopped matching, `pnpm test` would go green while running nothing.
Fix: remove `passWithNoTests`.

### New minor findings (owner: game-dev)

**n4. Non-canonical relative paths bypass the escape check.** eslint.config.js:59, 70-71. The
escape regex only looks at a leading run of `../`, and the bare-specifier regex lets any `./` or
`../` through. The probe gets **ok** for all of these:
- src/core/math/a.ts: `import x from './../../game/x'` (escapes into game)
- src/core/math/a.ts: `import x from '../x/../../game/x'` (escapes into game)
- src/data/a.ts: `import { add } from './../core/math/vec2'` (value import from core, against ADR 0003)
- src/data/missions/a.ts: `import type { S } from '../../core/../game/x'` (reaches game)

Nobody writes these on purpose, and IDE auto-import produces canonical paths, so the risk is low.
It is still a hole in a guard whose job is "no silent regression".
Fix: add one pattern to every `layerBoundary` block that rejects non-canonical specifiers. This
regex flags `./..` and any `..` that follows a non-`..` segment, and nothing else:
`{ regex: '^\\./\\.\\.(?:/|$)|(?:^|/)(?!\\.\\.(?:/|$))[^/]+/\\.\\.(?:/|$)', message: 'Use a canonical relative path.' }`.
I checked it in Node against `./../../game/x`, `../x/../../game/x`, `../../core/../game/x` and
`./x/../y` (all flagged), and against `../../types`, `../types`, `./game`, `../main`, `..`,
`./spells`, `@core/types` and `../../../../game/x` (none flagged).

**n5. Files deeper than `MAX_LAYER_DEPTH` get false positives.** eslint.config.js:38, 57-64.
The deepest block (`src/core/*/*/*/**/*.ts`) uses the depth-4 escape, so a legal 4-up import from
a depth-5 file is blocked: src/core/a/b/c/d/a.ts → `'../../../../types'` (which stays inside core)
is **blocked**. It fails safe (real escapes are still caught, e.g. `'../../../../../game/x'` is
blocked), and nesting this deep is unlikely.
Fix: raise `MAX_LAYER_DEPTH` to 6-8, which costs nothing at runtime, and make the comment at :37
say that deeper files fail safe.

**n6. An inline `type` specifier passes ADR 0003 but still emits a runtime import.**
src/data/a.ts `import { type V } from '@core/types'` is accepted. The core rule treats "all
specifiers are type" as a type import (no-restricted-imports.js:372-375). But tsconfig.json has
`verbatimModuleSyntax: true`, and `ts.transpileModule` turns that line into
`import {} from '@core/types';`, a side-effect import of a core module at runtime. `import type`
compiles to nothing. That goes against the ADR's intent that data reaches core only for types.
Fix: enable `'@typescript-eslint/no-import-type-side-effects': 'error'` (all src, or at least
src/data). It reports exactly this case and autofixes it to `import type { V }`.

Verdict for T1 overall: **PASS WITH NOTES**. n4-n6 are minor, have cheap fixes, and none blocks
M1. When game-dev lands n4 and n6, core-dev adds one regression case each.
