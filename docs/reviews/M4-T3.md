### Nit

**n1. A stale carry can make the first shot after idling up to one frame early.** (owner: core-dev)
cooldown.ts:26-37. When a cooldown crosses zero, the overshoot of *that* frame stays in
`remainingMs` while the weapon sits ready with no target. When it finally fires, maybe seconds later,
`triggerCooldown` still subtracts that old overshoot, so the next shot comes up to one frame early.
This is bounded (≤ 16.7 ms at 60 fps, ≤ 100 ms after a clamped hitch, i.e. one 400 ms spark cycle
25 % short in the worst case) and never banks more than one frame, so the "never banks shots" claim
holds. If you want it exact, keep the carry only when the trigger happens on the frame the cooldown
became ready: for example, `tickCooldown` clamps to `0` when called on an already-ready cooldown.
Optional.

**n2. `units()` copies and sorts on every call.** (owner: core-dev)
world.ts:73-75. Fine at M4 sizes. If `TargetingSystem` and the views call it several times per
frame, consider caching the sorted list until `add`/`remove`. No action now.

**n3. Area sources must go through `applyEventHits`, or the gib cap is skipped.** (owner: core-dev, M5/M6)
`applyHit` applies `isGibKill` without a cap (damage.ts:47). In M4 no `canGib` source exists, so
this has no effect yet. For Kaboom (M5), Arcane Detonation and Convergence (M6), the caller must use
`applyEventHits`. A one-line warning in the `applyHit` doc ("single-target only; area events use
`applyEventHits` for the gib cap") would stop a future caller from skipping it. I'll check it in M5.
