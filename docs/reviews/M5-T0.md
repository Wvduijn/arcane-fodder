## Findings

### Blocker

### Major

### Minor

**m1. `CombustDef.blast` doc does not say kegs in the radius are triggered.** (owner: producer; D5)
GDD §7: "A keg inside the radius is triggered (Kaboom), because the explosion is fire." The comment
on `CombustDef.blast` reads "Enemy units and huts only", which a core-dev reading only types.ts could
take as "kegs are not considered". The sprint architecture (reactions.ts returns keg triggers) and
T6 cover it, so this is a wording gap, not a shape gap. Fix: when types.ts is next opened, extend
the comment to "Damages enemy units and huts only; kegs in range are triggered (fire)". Until then I
check it in T6 (test: Combust next to a keg starts its fuse) and T9.

### Nit

**n1. `SpellDelivery` projectile comment omits collision tiles.** (owner: producer)
GDD §4 says Fireball also explodes on a collision tile. Correct to leave out in M5 (Q1: no collision
layer until M7), but the comment should gain "or collision tile" when M7 opens.

**n2. plan.md mirror drops `readonly` on `spreadTo`.** (owner: producer)
plan.md shows `spreadTo: EntityId[]`, the file has `readonly EntityId[]`. Consistent with the rest
of the mirror (no `readonly` anywhere) and the header says the file is authoritative. No action.

  emit `status:applied` on wizards. I check both in tests.

  team filter lives in `resolveAreaEvent` (T4), so check that T4 exposes it per call, not per def.
- T5/T10: `spell:cast.from` must be the leader at cast time even if it dies before impact (Q4);
  Fireball flight start uses the same point.
- T10: `spell:denied` must not be emitted on cooldown presses (Q4); `spell:lost` emitted from the
  diff of two derivations, never from a stored flag.
