## Verdict: CHANGES REQUIRED (one major, the producer's wiring gap 2; fix in progress)

What's right:
- **Data-driven setup.** Roster, name seed (+ attempt) and start come from `M01_GOBLIN_WOODS`
  and the map. Kegs, huts, spawn groups, archer posts, triggers, the portal and the surge all come
  from map objects. The dev arena isn't in the runtime path anymore (Q5).
- **Frame order** matches the sprint: input → mission → (collision) → squad → navigation →
  enemies → spawner → targeting → Convergence → Volunteer! → spells → kegs → combat → statuses →
  portal → late checks (extraction after deaths, then defeat) → HUD → views → camera → debug.
- **Gameplay vs presentation.** Gameplay steps only while `run.playing`. Presentation steps every
  frame, which freezes enemies after the end and during the intro.
- **Seeds.** Seeds are salted per use (scatter, surge, barks, Convergence), so they don't mirror
  the name draws.
- **Debug keys.** Mission debug keys (H destroy next hut, O open portal, I warp to portal, U warp
  to hut) exist only with `?debug` (`MissionScene.ts:336-358`).
- **SHUTDOWN.** Reverse system teardown, every `destroy()` runs even if one throws, and the overlay
  scenes are stopped (`:524-565`).

## Findings

### Major

**M1. The initial spawn scatter runs before the keg solids exist** (producer's wiring gap 2) —
`MissionScene.ts:166` builds `SpawnerSystem`, whose constructor spawns every start group
(`SpawnerSystem.ts:121`, `scatterPositions` with `placement.grid`). `KegSystem`, which registers
the 17 keg solids, is only built at `:174`. So the scatter's "off solids" check
(`spawns.ts`, M7-T11) sees no kegs for the start groups, and a grunt can be placed on a keg and
popped out on its first move. On m01 today no start group reaches a keg (level-designer's
"radius + 20" rule, M7-T4-T5 addendum), so there is no visible effect yet. But the core fix the
producer assigned for spawns on kegs is silently bypassed for every start group.
Fix: build `KegSystem` before `SpawnerSystem`, or move the start-group spawning out of the
constructor into a `start()` called after every solid is registered. Add a check (debug or test)
that no initial enemy overlaps a solid. Owner: **game-dev**. **Status: open**, re-check pending.

### Minor

**m1. The intro skip consumes `spell1`/`spell2`** (`MissionScene.ts:441-445`). That's good: the
click that skips the pan doesn't also cast. But the sprint says "any movement key or click", and
the Convergence (R/Space) and Volunteer (F) keys don't skip; they are simply ignored until play.
That's acceptable. Note it for the CD only if a playtester presses Space to skip.
