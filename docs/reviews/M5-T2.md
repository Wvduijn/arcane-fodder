## Findings

### Blocker

### Minor

**m1. The keg blink's §1.9 exemption extends a CD decision.** (owner: game-designer, via producer for CD confirmation; D5)
readability.md:257 marks the white/`crimson` keg blink as "exempt from the §1.9 cap like the hit
flash". The §1.9 exemption (CD decision 2026-10-16, M4 T12) covers sprite hit flashes (§1.8) only.
The blink alternates to white at 10 Hz, and a 3-keg chain runs three of them in sequence. §4 already
approved a "rapid white/red blink", so the look itself isn't new, but the exemption is a flash-safety
call that belongs to the CD. Fix: either get CD confirmation and note it next to §1.9, or change the
blink to a non-white pair (for example `crimson`/`flame` tint), which is outside "flash" and needs
no exemption.

**m2. Ember arc timing conflicts with "views only read state".** (owner: game-designer; D4)
readability.md:255 says the arc "lands as the target's Burning overlay starts", 200 ms after the
Combust. Core applies Burning at Combust time and emits `status:applied` then. To follow the spec,
the view would have to hold back an overlay for state that already exists. A target that dies
within those 200 ms would then show its charred death without ever showing Burning. Fix: start the
overlay on `status:applied` as now, and make the arc decorative ("lands on a target that is
already burning"). Or, if the delayed overlay is wanted, state explicitly that it's a view-only
200 ms delay and what happens on death mid-arc.

**m3. `cream` is "Units and FX only" in the style guide.** (owner: game-designer, confirm with art-director)
style-guide.md:94 restricts `cream`. §5b uses it for the ready border, badge border, key letters and
seconds text. The HUD is neither a unit nor FX. It's probably fine (cream on an `ink` plate is the
obvious UI choice), but the palette rule should say so. Fix: art-director adds "and UI text" to the
`cream` row, or §5b picks the UI colour the art-director names.

### Nit

**n1. "No non-integer scaling" can't hold on a phone.** (owner: game-designer)
§5b says integer positions and no non-integer scaling of the icons. The canvas uses `Scale.FIT`
(src/app/config.ts:21). At 844×390 it scales ×1.083, so on that device every pixel is scaled by a
non-integer factor, HUD included. (1280×720 and 2560×1440 are ×2 and ×4.) Suggest wording it as
"integer positions and no extra scaling within the 640×360 logical view". The physical scale is
FIT's.

**n2. The badges show Q/E only.** (owner: game-designer)
Left and right click also cast slot 1 and slot 2 (src/game/input/KeyboardMouseInput.ts:31-32). This
is fine for M5. Worth a line in the M8 tutorial or touch-layout notes so mouse players learn it.

**n3. The style guide §10 flash-safety reference is stale.** (owner: art-director)
style-guide.md:369 cites "readability.md §1.7" for flash safety. It's §1.9 now. This isn't part of
T2, but it's the reference T11 will follow.
