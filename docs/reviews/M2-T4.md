## Producer's three points

### TILE_SIZE_PX = 16 in src/game: acceptable for now, keep it there

- It is not a tuning value. Designers won't tweak it for feel. It's the content format fixed by
  tiled-conventions.md:21 and style-guide.md:45 ("Tiles 16 × 16"). CLAUDE.md's "designers change
  numbers in src/data" rule is about tuning.
- Its only consumers are placeholder rendering: the canvas size of the ground textures
  (placeholders.ts:64-72) and the border thickness (PlaceholderGround.ts:13-19). No gameplay rule
  reads it.
- In M7 the real value comes from the map JSON (`tilewidth`/`tileheight`), which TilemapLoader
  reads. Putting a copy in src/data now would create a second source of truth that M7 has to delete.
- **Condition:** once gameplay code needs tile size (e.g. converting the GDD's "5 tiles" into
  pixels), it must come from map data or a src/data constant owned by level-designer, not from
  placeholders.ts. Nit: extend the comment at placeholders.ts:13 to say "placeholder rendering only;
  M7 reads tilewidth from the map".

### The leader position is authoritative and the sprite only reads it: OK

- `current` is private, and the only reads go through the `position` getter (LeaderController.ts:37-39).
  `update()` computes the new position from `current` and then pushes it to the sprite (:41-50).
  Nothing reads `sprite.x/y` back.
- The start position goes through `clampToRect` too (:30), so an out-of-bounds spawn is corrected
  before the first frame.
- `Positioned` (:11-13) is a good narrow interface for T5 and T6 to depend on, rather than the
  whole controller.

### Shutdown order: OK

- `create()` registers `events.once(SHUTDOWN, …)` (MissionScene.ts:30). It's `once`, and
  `create()` runs again on restart, so there's exactly one listener per run with no stacking.
- `handleShutdown` destroys systems in reverse order, then the input, which was created first and
  so is destroyed last. It also clears both fields, so a stray `update()` after shutdown does
  nothing (:38-43).
- Phaser's DisplayList also listens for SHUTDOWN and may destroy the leader sprite before our
  handler runs. `LeaderController.destroy()` → `sprite.destroy()` is still safe, because
  `GameObject.destroy` returns early on an already-destroyed object (GameObject.js:1009).
- The ground tileSprites are scene-owned display objects, and Phaser cleans them up. That's
  documented at PlaceholderGround.ts:8.
- `gameInput.update()` runs before every system (:34-35), as T3's class comment requires.
- `dt` is the Phaser loop `delta`, which satisfies the "Phaser clock only" rule.

A restart-leak count (×10 restarts) belongs to T6 and the gate.

## Findings

### Blocker
None.

### Major

**M1. The sprite is anchored at its centre, not at the feet where the GDD puts the body circle.**
(owner: game-dev)
LeaderController.ts:31-34 uses the default origin (0.5, 0.5). GDD mvp.md:37 says every unit "has a
collision circle **at its feet**", and style-guide.md:51 and :63 fix the anchor for every 48 × 48
character at **(24, 46)**. So `position`, which is what gets clamped, followed by the camera and
(from M3/M4) used for trail spacing, separation, area hits and the 112 px extraction check, is
currently 22 px above the feet. Effects:
- At the bottom world edge the clamp stops the centre 10 px from the edge, so the feet and the
  lower 14 px of the robe sit beyond the map and the camera bounds cut them off. The wizard looks
  like they're sinking into the edge. At the top edge the gap between the visible feet and the
  edge is wrong for the same reason.
- If this isn't fixed now, M3+ code gets written against "position = sprite centre", and changing
  it later moves every distance check by 22 px.

Fix: anchor the sprite at the style-guide point, e.g. in placeholders.ts
`export const CHARACTER_ANCHOR = { x: 24 / 48, y: 46 / 48 } as const;` with a comment pointing to
style-guide §6, then `.setOrigin(CHARACTER_ANCHOR.x, CHARACTER_ANCHOR.y)` in LeaderController.
The placeholder art's feet are on row 15 of 16, so at ×3 they land on rows 45-47, which matches
46. When real atlases arrive (M8), the anchor should come from tech-artist's src/data/animations.ts
rather than placeholders.ts. After the fix the top-edge clamp shows the hat partly off-map. That's
expected: the body circle, not the sprite, is what stays inside the world.

### Minor
None.

### Nits (owner: game-dev, optional)
- placeholders.ts:13: add the comment noted under TILE_SIZE_PX above.
- `Positioned` lives in LeaderController.ts. When T5 and T6 import it from there, the camera and
  debug code will depend on the leader module. Consider moving it to src/game/entities/Positioned.ts
  (or next to `System`) when T5 lands. That's cheap now and churn later.
- `delta` isn't capped. It's harmless in M2 because the clamp keeps the leader in the world even
  on a long frame. From M7 on, a large dt could tunnel through blockers, so revisit a max-dt clamp
  (as a data value) when collision arrives.
