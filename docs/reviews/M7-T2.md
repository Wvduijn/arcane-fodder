## Verdict: PASS WITH NOTES

A dependency-free Node ESM script. It turns an ASCII terrain grid (with `(cN)` runs) and an
objects JSON into a Tiled 1.10 JSON map:
- The map is orthogonal and not infinite, with 16 px tiles.
- It has the four tile layers and four object layers in the conventions §3 order.
- It embeds three tilesets named and keyed per conventions §7, and every tile carries a `name`
  property, so no tile ids appear in game code.
- Objects get their layer and point or rect geometry from their type, plus typed Tiled
  properties.

The README is clear: the format, the default legend, the tile catalogue, and the objects JSON
with examples. It explains why the portal pad is walkable, and the conventions §3 amendment
matches it.

The build is deterministic. Rebuilding m01 gives a byte-identical file.

## Findings

### Minor

**m1. The generator has no automated test** — none of `tests/**` runs `buildMap`. The stub folder
(`scripts/levels/stub/`) is ready-made input. One Vitest case that builds the stub to a temp file
and parses it with `parseMissionMap` would lock the format contract between T2 and T9, so a
generator change can't silently produce a map the loader rejects.
Owner: **game-dev** (writes the case) via **core-dev** (owns `tests/**`).

**m2. An object's first error hides its duplicate-name error** — `build-tilemap.js:322-323`.
`names.add(name)` only runs for an object with no issues, so a second object with the same name
as a broken first one isn't reported as a duplicate. The loader (T9 rule 5) still catches it,
so this is low impact. Fix: add the name to `names` before throwing. Owner: **game-dev**.

**m3. Points exactly on the right or bottom edge pass** — `:310-314` uses `right > size.width`.
A point at `x = width` lies outside the last tile and outside the collision grid's bounds. The
loader has the same `>` test (`mapData.ts:316`). Fix both to `>=` for points. Owner: **game-dev**
(script), **core-dev** (loader).

**m4. Tileset `image` points at PNGs that don't exist** (`tiles-forest-ground.png`, …,
`:357`). The game paints placeholders by tile name, so play is unaffected, but Tiled opens the
map with missing-image warnings and draws empty tiles. The README says the output "still opens in
Tiled". Either note in the README that tiles show blank until art lands, or have `maps:build`
emit placeholder PNGs next to the map. Owner: **game-dev**.

### Observation

- **o1.** Typed properties accept `{ "type": "int", "value": "abc" }` without checking the
  value's type (`:260-265`). The loader rejects the bad value later with the object's name, so
  this is caught; it's just one step later than it could be.
