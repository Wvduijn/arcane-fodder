### Minor

**m1. plan.md §7.4 event map is now out of date.** (owner: producer, needs CD approval to edit plan.md; D1)
plan.md:400-405 still shows `'unit:damaged': { id; amount; source }` (no `team`, `element`),
`'unit:died'` without `deathVariant`/`gibbed` and with the old `cause: 'combat' | 'volunteer'`,
and no `status:expired`. CLAUDE.md says plan.md is the source of truth, so a later task written
from §7.4 could re-derive the old shapes. TypeScript catches emitters, but not intent.
Fix: update the §7.4 block to mirror src/game/events.ts (or replace it with "see src/game/events.ts"),
next time plan.md is opened with CD approval. Not blocking M4.

### Nit

**n1. `Element` shares its name with the DOM global `Element`.** (owner: producer)
tsconfig.json:6 includes the `DOM` lib for all of `src`, `src/core` included. A file that writes
`element: Element` and forgets the import gets lib.dom's `Element` instead of an error at the
declaration. Assigning `'fire'` to it would still fail, so the risk is low, and plan.md:297 names
the type `Element`. No action needed now; if it bites, rename to `MageElement` in a later
contract round.

**n2. `MeleeAttackDef` doc cites "M4 Q2" where the sprint block says "Q3".** (owner: producer)
The code is the more accurate reference (Q2 approved the whiff, Q3 the wind-up value). No action.
