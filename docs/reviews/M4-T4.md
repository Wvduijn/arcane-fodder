### Minor

**m1. With the scene's frame order, a fresh or refreshed Burning loses one frame.** (owner: core-dev, with game-dev for T11; D3)
The sprint's frame order is `CombatSystem → StatusSystem`. A fire bolt that lands in frame N's
`CombatSystem` calls `applyStatus` (`nextTickInMs = 500`, `remainingMs = 3000`). Then, in the
*same* frame, `stepStatuses(dt_N)` subtracts dt_N, which is time that elapsed *before* the hit. So the
first tick comes 500 − dt after the hit (483 ms at 60 fps, 400 ms on a clamped 100 ms frame), and a
refresh shortens the duration by the same amount. The unit tests don't see this because their
`run()` harness applies at frame start (status.test.ts:30) or *after* the step (:44-47).
That's within the "one frame" slack D3 allows, but it's a systematic early bias, and the encounter
sim (T8) will inherit it. Fix, either:
- core: `applyStatus` marks the instance as fresh, and `stepStatuses` skips the decrement for fresh
  instances on their first step (then clears the mark), with a test that applies *between*
  `applyHit` and `stepStatuses` the way the scene does; or
- game: `StatusSystem` steps statuses *before* `CombatSystem` resolves this frame's hits. That changes
  the approved frame order, so it's a producer call.
The core fix keeps the frame order and is the one I recommend.

**m2. A killing tick on the expiry frame reports both expiry and death.** (owner: game-dev, T11)
`stepStatuses` deletes the status and reports `expired` before the caller applies the ticks
(status.ts:92-96). When the last tick (the one exactly at expiry) kills, the same frame yields
`expired` for the unit *and* a death. Emitting both breaks the `status:expired` contract ("Not emitted
on death"). Fix in `StatusSystem`: apply the ticks first, then emit `status:expired` only for ids
still `world.isAlive`. A core test could pin it as well (apply to a 3-HP unit, step 3000 → one tick
kill, expiry listed, so the caller must filter). Alternatively, core-dev can document on
`StatusStepResult.expired` that callers filter by `isAlive`.
