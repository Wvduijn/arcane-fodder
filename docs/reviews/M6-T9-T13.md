## Verdict: PASS WITH NOTES

The game layer is a thin adapter over core, as the architecture asks:
- ConvergenceSystem feeds core's meter from `unit:damaged`/`unit:died` and allocates the two
  credit ids from the run's allocator. It steps core's channel, resolves every blast through
  `CombatSystem.resolveArea`, and emits `convergence:impact` with the blast `element`.
- VolunteerSystem marks the runner's death cause at activation and detonates fallen runners in a
  `beforeDeathFlush` hook, so `volunteer:detonated` precedes the single `unit:died` (cause
  `volunteer`) on the same frame. That closes M6-T6 M1 end to end.
- CombatSystem credits every reaction with core's `outcome.sourceId`. The M5 re-derivation is gone.
- Storage goes only through `LocalStorageSaveRepository`, which is guarded, cached, uses
  `readSave`/`canOverwrite` and never overwrites a newer save. It's created once in main.ts and
  passed down.

Every new listener has a matching `off` (ConvergenceFxView 3/3, VolunteerFxView 2/2, HudModel
6/6). FX are pooled, and pool `created` counts don't grow across repeated casts. Lifecycle counts
are flat across 4 restarts, including mid-channel and mid-sprint. No console errors. No blockers,
no majors.

### Minor

**m1. `src/game` imports the `SaveRepository` interface from `src/platform`.** (owner: game-dev;
producer if the layer rule should change)
src/game/save/SavedHatHill.ts:3 and src/game/services.ts:1 have
`import type { SaveRepository } from '@platform/storage/SaveRepository'`. plan §7.1 draws platform
above game, with dependencies pointing down only, so game should not depend on platform, even for
a type. ESLint (§7.3) doesn't forbid it, which is why lint passes. It's type-only and harmless at
runtime, but it's the first game→platform edge and it will grow (M9 lifecycle, Capacitor). Fix:
move the `SaveRepository` interface down (src/core/save/ next to `SaveData`, or src/game/save/),
and let `LocalStorageSaveRepository` in platform implement it. Optionally the producer adds a
`no-restricted-imports` rule for `src/game/** → @platform/*` (wiring stays in src/app and main.ts).

### Nit

**n1. Auto cooldowns freeze during the channel.** TargetingSystem returns before ticking, so a
wizard 0.1 s from firing fires 0.1 s after release. GDD §10 only says "no autos", so this is
harmless. game-dev listed it as a known limitation. Leave it unless the CD wants autos to come back
"ready" after a channel.

**n2. The debug overlay text runs under the HUD meter at 1280×720.** The `react … flashes … shakes`
line overlaps the meter bar in t13-02-channel.png. It's debug only, but it makes D5 screenshots
harder to read. Toggle the overlay off for HUD screenshots (game-dev's harness does) or end the
panel above y ≈ 330.

**n3. A wipe while a volunteer sprints.** If the last squad member dies while a runner is still
out, the squad is empty but a squad-team unit lives on until its fuse. Nothing in M6 depends on
it. M7's defeat rule should say whether the runner counts. I'll raise it at the M7 kickoff.
