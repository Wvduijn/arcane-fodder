## Verdict: PASS WITH NOTES

- **Loader.** The loader only fetches and hands the JSON to core: `parseMissionMap` in a cached
  `parsedMap`. Warnings are logged, errors are logged *and* thrown, so a broken map fails loudly in
  dev. Missing required layers or tilesets throw with the map key. Tile textures come from tile
  names (`createPlaceholderTilesets`), so no tile ids appear in code.
- **Layers and bounds.** Layers get their depths in conventions §3 order (ground, ground-detail,
  blockers, canopy). World and camera bounds are `tilemap.widthInPixels/heightInPixels`, and
  `tilemap.destroy()` runs on SHUTDOWN after every system.
- **CollisionSystem** wraps `collisionGridOf(map)` and keeps a solid registry, whose count is
  exported to the leak log.
- **NavigationSystem.** It rebuilds the flow field on the `FlowFieldClock` at
  `NAVIGATION.flowFieldRebuildMs` (data, not code), and invalidates the clock on `kaboom` (a keg's
  solid leaves) and on `hut:destroyed`. A wiped squad keeps the last field. Both listeners are
  removed in `destroy()`.
- **Wiring gap (3) is fixed.** `refreshNavigation: () => navigation.tickedThisStep`
  (`MissionScene.ts:163`) goes to `EnemyAiSystem.ts:246-247`. Navigation runs before enemies in
  the frame order (`MissionScene.ts:363-368`), so the core per-enemy cache from M7-T7 refreshes
  only on the 250 ms tick, as intended.
